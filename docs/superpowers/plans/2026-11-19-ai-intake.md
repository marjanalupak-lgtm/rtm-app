# AI intake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An **AI** button in the RTM toolbar that sends pasted text and files to Claude, shows proposals (new / update / duplicate / conflict) with a summary, and applies the ticked ones.

**Architecture:** Pure modules under `src/ai/` (prompt + schema, file → content blocks, client + key, apply planner) with unit tests; one UI component `src/AiPanel.tsx`; a Settings › AI section; small store change for history actions. Claude is called from the browser with the user's key via the official SDK.

**Tech Stack:** React 19 + TypeScript + Vite, EPAM UUI, Vitest, `@anthropic-ai/sdk` (1.10.0), `mammoth` (1.13.0), existing `xlsx`.

**Spec:** `docs/superpowers/specs/2026-11-19-ai-intake-design.md`

## Global Constraints
- Model `claude-opus-5-5`; streaming + `finalMessage()`; `max_tokens: 32000`; `output_config: { effort: "high", format: { type: "json_schema", schema } }`; server fallbacks `betas: ["server-side-fallback-2026-07-01"], fallbacks: "default"` (beta messages endpoint).
- SDK client: `new Anthropic({ apiKey, dangerouslyAllowBrowser: true })`.
- Key only in `localStorage['rtm.ai.key']`; never in config, sheet, export, or repo.
- Request limit 32 MB total; refuse (don't truncate) with the file name.
- Nothing is written until **Apply**. Duplicates/conflicts unticked by default; new/update ticked.
- Updates may change only: `statement, acceptance, priority, category, parent, notes`.
- History actions: `ai-intake` (new rows), `ai-update` (updates).
- UI copy: "Your text and files are sent to Anthropic (Claude)." and "Stored only in this browser. Not saved to the project or Drive."
- Button hidden when `project.canEdit === false`. No audio.

## Review Focus
1. Claude output cut off (`stop_reason: "max_tokens"`) or invalid JSON → clear error "Result was too long — split the input", no partial apply. (Task 3 test)
2. A proposal's `parent` names a `tmp-` ID that isn't in the batch or isn't ticked → parent left as written text + flagged, not a broken link. (Task 4 test)
3. Two new proposals of the same type+area → consecutive IDs, no collision with existing ones. (Task 4 test)
4. Empty input (no text, no files) → Analyse disabled. (Task 7)
5. Proposal with area unknown to Settings › IDs → flagged, Apply blocked for that card until an area is picked. (Task 4 test)

### Task 1: Prompt, schema and result types

**Files:** Create `src/ai/prompt.ts`, Test `src/ai/prompt.test.ts`

**Interfaces — Produces:**
- `type ProposalKind = 'new' | 'update' | 'duplicate' | 'conflict'`

- `type AiResult = { summary: string; structure: string[]; proposals: Proposal[]; questions: string[]; nextSteps: string[] }`
- `RESULT_SCHEMA` (JSON schema object; all fields required, `additionalProperties: false`; `changes` as array of `{field, value}` in the schema, converted to a record by `parseResult`)
- `buildSystemPrompt(rows: Req[], cfg: Config): string`
- `parseResult(json: string): AiResult` (throws `Error('bad-json')`)

- [ ] **Step 1: tests** — `buildSystemPrompt` contains one line per requirement `ST-FR-001 | Functional | ST | ST-SR-01 | <statement>` (statement whitespace collapsed, ≤ 300 chars), lists `cfg.lists.type`, the area codes with names, and the rule text "Never invent IDs for new items; use tmp-1, tmp-2…". `parseResult` on a valid sample returns `changes` as a record; on `'{'` throws `bad-json`. Output is deterministic (same rows → same string, rows sorted by id) so the prompt caches.

### Task 2: Files → content blocks

**Files:** Create `src/ai/inputs.ts`, Test `src/ai/inputs.test.ts`; `npm i mammoth@1.13.0 @anthropic-ai/sdk@1.10.0`

**Interfaces — Produces:**
- `type Block = Anthropic.ContentBlockParam` (text | image | document)
- `fileToBlocks(file: File): Promise<Block[]>` — PDF → `document` base64; png/jpeg/webp/gif → `image` base64; .txt/.md/.vtt/.srt/.csv/.json → `text` block prefixed `File: <name>\n`; .docx → mammoth `extractRawText` → text; .xlsx/.xlsm → each sheet `XLSX.utils.sheet_to_csv` → text. Other types → `throw new Error('unsupported:' + name)`.
- `MAX_BYTES = 32 * 1024 * 1024`; `checkSize(files: File[], text: string): string | null` → name of the file that pushes the total over the limit (base64 counts as ×4/3), else null.

- [ ] **Step 1: tests** — `.txt` → one text block starting `File: notes.txt`; `.vtt` same; `.exe` → rejects `unsupported:a.exe`; `checkSize` with a 25 MB fake file (`new File([new Uint8Array(25e6)], 'big.pdf')`) returns `'big.pdf'`, with 1 KB returns null.
- [ ] **Step 2:** FAIL → **Step 3:** implement (base64 via `FileReader.readAsDataURL`, strip prefix) → **Step 4:** PASS
- [ ] **Step 5:** commit `feat(ai): read files into content blocks`

### Task 3: Client and key

**Files:** Create `src/ai/client.ts`, Test `src/ai/client.test.ts`

**Interfaces — Consumes:** Task 1 (`buildSystemPrompt`, `RESULT_SCHEMA`, `parseResult`, `AiResult`), Task 2 (`Block`).
**Produces:**
- `getKey(): string | null`, `setKey(k: string): void`, `clearKey(): void` (try/catch around localStorage)
- `type AiErrorKind = 'no-key' | 'bad-key' | 'busy' | 'too-large' | 'refused' | 'too-long' | 'bad-json' | 'network' | 'other'`
- `class AiError extends Error { kind: AiErrorKind }`, `explain(kind: AiErrorKind): string` (user-facing text)
- `toAiError(e: unknown): AiError` — `Anthropic.AuthenticationError` → bad-key; `RateLimitError` / status 529 / `InternalServerError` → busy; status 413 → too-large; `APIConnectionError` → network; `Error('bad-json')` → bad-json
- `runIntake(a: { rows: Req[]; cfg: Config; text: string; blocks: Block[]; signal?: AbortSignal }): Promise<AiResult>` — system prompt as a text block with `cache_control: { type: 'ephemeral' }`; user content = blocks then text; checks `stop_reason`: `'refusal'` → refused (message includes `stop_details?.explanation`), `'max_tokens'` → too-long; reads the first text block and `parseResult`.
- `testKey(key: string): Promise<void>` — `client.models.retrieve('claude-opus-5-5')`; throws `AiError`.

- [ ] **Step 1: tests** — key round-trip; `toAiError` maps `new Anthropic.AuthenticationError(401, …)`-like objects (construct via `Object.assign(Object.create(Anthropic.AuthenticationError.prototype), {status: 401})`) → `bad-key`; `{status: 529}` APIError → `busy`; `new Error('bad-json')` → `bad-json`. A `handleResponse(msg)` helper (exported for tests) returns `too-long` for `stop_reason: 'max_tokens'` and `refused` for `'refusal'`.
- [ ] **Step 2:** FAIL → **Step 3:** implement → **Step 4:** PASS
- [ ] **Step 5:** commit `feat(ai): Claude client, key storage, errors`

### Task 4: Apply planner

**Files:** Create `src/ai/apply.ts`, Test `src/ai/apply.test.ts`

**Interfaces — Consumes:** `Proposal` (Task 1); `nextSchemeId`, `IdScheme` (`src/idScheme.ts`); `nextIdFor` (`src/rules.ts`); `emptyReq` (`src/model.ts`).
**Produces:**
- `UPDATABLE = ['statement', 'acceptance', 'priority', 'category', 'parent', 'notes'] as const`
- `type Defaults = { release: string; owner: string; source: string; date: string }`
- `cardProblem(p: Proposal, cfg: Config): string | null` — "unknown area" when the type uses areas and `p.area` isn't a project area; "missing type" for `new` without a type in `cfg.lists.type`; "unknown requirement" for update/conflict whose `existingId` isn't in rows.
- `planApply(selected: Proposal[], rows: Req[], cfg: Config, d: Defaults): { creates: Req[]; updates: { prev: Req; next: Req }[]; idMap: Record<string, string>; warnings: string[] }`
  - new → IDs assigned in list order against `rows + creates so far`; `tmp-` parents replaced via `idMap` (unknown tmp → kept as text + warning `"<tmp> not in this batch"`); fields: type, statement, acceptance, priority, category, `design_required` = p.designRequired || '', release/owner/source/date from `d` (p.source overrides `d.source` when set), `status = cfg.workflow.initial`, `delivery = 'Not Started'`, `notes = 'From AI intake: ' + p.reason`.
  - update / ticked conflict → copy of the existing row with only `UPDATABLE` keys from `p.changes` applied; other keys in `changes` ignored + warning.
  - duplicate → ignored.

- [ ] **Step 1: tests** — two `new` Functional/ST proposals with existing max ST-FR-089 → `ST-FR-090`, `ST-FR-091`; a `new` SR with tmpId `tmp-1` and an FR whose parent is `tmp-1` → FR.parent = the SR's new ID; parent `tmp-9` (absent) stays `tmp-9` + warning; update with `changes {statement:'x', type:'Business'}` → statement changed, type unchanged, warning names `type`; `cardProblem` → "unknown area" for area `XX`.
- [ ] **Step 2:** FAIL → **Step 3:** implement → **Step 4:** PASS
- [ ] **Step 5:** commit `feat(ai): plan which rows to create and update`
